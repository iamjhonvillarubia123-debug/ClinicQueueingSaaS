## 4. Defect found during acceptance and correction

During BookingGroup -> BookingGroup replacement through unified recovery, PostgreSQL rejected creation of the replacement `OtpVerification` row with check constraint `OtpVerification_timestamp_order_check`.

Root cause:

- replacement `verifiedAt` used the application `now` timestamp;
- `createdAt` was independently generated by PostgreSQL;
- under the observed timing, the row could appear verified before its recorded creation time.

Correction:

- the replacement OTP record now receives one explicit timestamp for both `createdAt` and `verifiedAt`;
- the database timestamp-order constraint was retained unchanged;
- regression coverage verifies the invariant.

Relevant commits:

- `6ae232bd30ad7952a1c3246a09614456e091c476` - replacement OTP timestamp-order fix;
- `a076bfec85192635aad9373a56f2ec58d2785cf0` - replacement-authority regression test.

The corrected Group -> Group browser acceptance subsequently passed.
